# BOSS 直聘海投助手 1.1.13 · Edge 独立扩展

本扩展不需要油猴。安装包请先解压，再在 Microsoft Edge 中加载。

## 安装

1. 在 Edge 地址栏输入 `edge://extensions`。
2. 打开「开发者模式」，点击「加载解压缩的扩展」。
3. 选择当前这个直接包含 `manifest.json` 的文件夹。
4. 停用以前的油猴版助手，刷新 BOSS 页面。
5. 在面板填写并保存配置，点击「开始」才会运行。

不要直接把 ZIP 拖进扩展页。安装完成后保留当前文件夹；移动或删除它会导致扩展不可用。更新文件后，在扩展管理页刷新扩展，再刷新 BOSS 页面。

## 配置

旧油猴版的私有配置无法自动读取，请重新填写规则、AI 接口和密钥；旧版当日额度也不要视为已迁移。

关闭 AI 或没有配置完整接口时可直接使用完整本地规则。必含词支持 MCU/单片机、C++/CPP 等技术词别名；明确的技术培训、非外包等上下文不再误跳过。

使用 AI 时，打开 Edge 工具栏里的本扩展按钮，可选择“一次授权，新增 API 免重复授权”。该选项需要你在浏览器提示中允许扩展访问所有 HTTP/HTTPS 网站；允许后，新增接口域名、修改 Key 和拉取模型均复用权限，无需先保存接口，可在扩展权限设置中撤回。也可先保存接口再选择“仅授权已保存域名”，同一域名只需一次。这里是浏览器访问权限，不是 API Key 验证；助手仍仅自动注入 BOSS 页面，后台只向你填写的接口发起模型列表或对话请求。

AI 按设置顺序依次判断，第一个不可用立即试下一个。全部失败时保留当前岗位，等待一分钟后从第一个开始全部重试，持续循环；可随时暂停、停止或关掉 AI。插件 AI 调用次数不限，旧 100 次等配置不再阻断请求；调用尝试计数和每日投递上限仍保留。供应商 429/余额限制继续报出具体原因，本地存储失败则停止并提示修复，避免无效重试。

在 AI 设置的“限制与策略”中，“忽略年限和学历要求”默认开启：JD 的学历、工作年限和画像里的相关筛选条件不用于拒绝，技术技能与实际项目仍比较。关闭后仅采用画像明确写出的学历、经验筛选条件，身份描述不会自动成为门槛。“不投短期岗位”只过滤明确短期实习、项目制、劳务派遣或兼职等，普通实习与校招不因名称被拒绝；关闭则不因短期性质拒绝。“只按明确事实判断”开启后禁止推测性拒绝。

模型结论会复核这些策略，违规时同接口纠正重判一次；仍违规则试备用接口，全部失败保留当前岗位等待一分钟重试。违规结论不缓存，不直接拒投或放行；策略改变会使旧缓存失效。

开启 AI 后按投递机会筛选：已有相关技术或项目基础时优先尝试，未知能力留待面试确认。Linux 不是一票否决词，“熟悉、了解、优先”不能升级为“深入、精通、必备”；FreeRTOS 项目属于 RTOS 经验。画像明确排除、真实核心冲突或明确高级独立专家要求仍按事实处理，默认与自定义提示一致。

飞控等方向按真实固件、实时任务和相关项目比较；不能仅因职位标题或未提某技能就判断匹配/不匹配。

离线关联只使用当前岗位的实际职责，区分公司介绍、必备核心要求、明确否定和任选条件。

投递或判定不合适后，先切换并确认下一张，再进入批间休息。点击使用标题或主体的实际命中节点，未选中时尝试其他区域；已选中时先继续等待正文，避免重试点击打断慢加载，必要时再重新选择。成功框未关闭、停止、风控或额度已满时不继续推进。旧正文残留时继续拦截，提前选中的快照会重新校验。“准备调用”日志可查看本次职位 ID 和送入 AI 的正文，缓存命中另有标注。

招呼语在 BOSS 直聘手机 App 中设置。扩展仅点击 BOSS 官方沟通按钮；识别到“已向BOSS发送消息”或本次按钮变为“继续沟通”时标记绿色“成功”，关闭成功框后再处理下一家。实际内容与发送结果以 BOSS 消息页为准。

卡片在处理期间显示“读取中”“AI 重试中”“判断中”或“投递中”，本次投递结果显示“成功”或“失败”，附具体原因。“AI 通过”说明模型筛选通过；自动投递关闭时的“筛选通过”说明只完成筛选；“已沟通过”说明既有沟通记录。失败说明会区分读取阶段与已进入 AI 判断等实际阶段。已点击沟通但没有收到官方成功回执时，标为“失败”并提示到 BOSS 消息页核对；已发起的占额和去重继续保留。最近一笔操作在一分钟内收到同岗位的迟到成功回执时，原卡修正为“成功”并清理成功框，已经停止的任务保持停止。

换岗后原次回执监听永久失效，返回原卡也不会认领其他岗位的弹窗。请求 AI 或保存记录时卡片被替换，原岗位的状态不会写到新卡上。

配置保存在扩展本地存储；AI 请求发送到你配置并授权的服务。浏览器节能、标签页休眠和系统休眠仍可能暂停运行。

工具栏弹窗可显示助手或停止当前页面任务。只打开职位详情或加载扩展不会自动开始投递。

列表采用边处理边补加载：先处理已经出现的新岗位，分屏向下滚动加载；没有新增时向上回滚一段再重新到底，连续检查三轮后才停止。页面高度未变化、卡片被重复利用或混合显示时，仍按岗位身份识别未处理内容。

JD 默认全文发送，旧字数设置只在明确选择“手动裁剪”时生效；全文超过 20000 字会提示并停止。诊断保存本次实际输入和字段来源，不用后来修改的设置重新拼接旧记录。缓存命中注明没有新请求。

完整回归清理测试窗口及回调引用，保留岗位身份、投递次数和 AI 输入检查。具体验证结果见源码包的 VALIDATION.md。验证未向真实招聘方发送消息，实际内容与结果仍以 BOSS 消息页为准。
